# 题目二：查询执行详解

本文档非常详细地说明题目二“查询执行”要补哪些代码、每处代码写在哪个文件、每个接口怎么实现、为什么要这么实现、以及这些实现如何对应平台测试点。

题目二建立在题目一“存储管理”之上。题目一已经让系统具备了：

- 文件页读写能力：`DiskManager`
- 缓冲池换入换出能力：`BufferPoolManager`
- 记录插入、删除、更新、扫描能力：`RmFileHandle`、`RmScan`

题目二要在此基础上，让系统真正能执行 SQL：

- DDL：`create table`、`drop table`、`show tables`
- DML：`insert`、`delete`、`update`
- DQL：`select`
- 单表条件查询
- 多表连接查询

整条 SQL 执行链路如下：

```text
用户 SQL
  |
  v
Parser：语法解析，生成 AST
  |
  v
Analyze：语义分析，检查表、列、类型，补全表名
  |
  v
Planner：生成逻辑/物理执行计划
  |
  v
Portal：把执行计划转换为执行器树
  |
  v
Executor：真正读写记录、筛选、投影、连接
  |
  v
Record/Storage：操作表文件和缓冲池
```

## 三、SQL 在框架中的执行流程

理解题目二之前，必须先知道 SQL 在框架里怎么流动。

### 3.1 Parser 阶段

语法文件：

```text
rmdb/src/parser/yacc.y
```

AST 定义：

```text
rmdb/src/parser/ast.h
```

例如：

```sql
select score,name,id from grade where score > 90;
```

会被解析为：

- `ast::SelectStmt`
- `cols = [score, name, id]`
- `tabs = [grade]`
- `conds = [score > 90]`

Parser 只负责语法正确，不负责：

- 表是否存在
- 列是否存在
- 类型是否兼容
- 执行方式是什么

这些交给 Analyze 和 Planner。

### 3.2 Analyze 阶段

入口：

```cpp
std::shared_ptr<Query> Analyze::do_analyze(std::shared_ptr<ast::TreeNode> parse)
```

文件：

```text
rmdb/src/analyze/analyze.cpp
```

Analyze 要把 AST 转换为更适合执行的 `Query` 对象。

`Query` 定义在：

```text
rmdb/src/analyze/analyze.h
```

核心字段：

```cpp
class Query {
public:
    std::shared_ptr<ast::TreeNode> parse;
    std::vector<Condition> conds;
    std::vector<TabCol> cols;
    std::vector<std::string> tables;
    std::vector<SetClause> set_clauses;
    std::vector<Value> values;
};
```

其中：

- `tables`：SQL 涉及的表。
- `cols`：select 要输出的列。
- `conds`：where 条件。
- `set_clauses`：update 的 set 子句。
- `values`：insert 的 values。

### 3.3 Planner 阶段

入口：

```cpp
std::shared_ptr<Plan> Planner::do_planner(std::shared_ptr<Query> query, Context *context)
```

文件：

```text
rmdb/src/optimizer/planner.cpp
```

Planner 的作用是把 `Query` 转换成执行计划树，例如：

```text
select name from grade where id = 2;
```

可以生成：

```text
ProjectionPlan(name)
  |
  v
SeqScanPlan(grade, id = 2)
```

多表连接：

```sql
select t.id,t_name,d_name from t,d where t.id = d.id;
```

可以生成：

```text
ProjectionPlan(t.id, t_name, d_name)
  |
  v
NestedLoopJoinPlan(t.id = d.id)
  |                  |
  v                  v
SeqScanPlan(t)       SeqScanPlan(d)
```

### 3.4 Portal 阶段

文件：

```text
rmdb/src/portal.h
```

Portal 负责把 `Plan` 变成真正可执行的 `Executor`。

例如：

```cpp
ProjectionPlan -> ProjectionExecutor
ScanPlan       -> SeqScanExecutor
JoinPlan       -> NestedLoopJoinExecutor
```

执行器树会被交给 `QlManager::select_from` 或 `QlManager::run_dml` 执行。

### 3.5 Executor 阶段

执行器负责真正做事情：

- `SeqScanExecutor`：扫描表。
- `ProjectionExecutor`：抽取指定列。
- `NestedLoopJoinExecutor`：连接两张表。
- `InsertExecutor`：插入记录。
- `UpdateExecutor`：更新记录。
- `DeleteExecutor`：删除记录。

## 四、系统管理器 SmManager 详解

文件：

```text
rmdb/src/system/sm_manager.cpp
```

题目二中的 DDL 主要依赖 `SmManager`。

### 4.1 `SmManager::create_table`

框架中已经提供了 create table 的主要实现。

核心逻辑：

```cpp
void SmManager::create_table(
    const std::string& tab_name,
    const std::vector<ColDef>& col_defs,
    Context* context)
```

做了这些事：

1. 检查表是否已经存在。
2. 构造 `TabMeta`。
3. 为每个列计算：
   - 表名
   - 列名
   - 类型
   - 长度
   - 在记录中的 offset
4. 调用 `rm_manager_->create_file(tab_name, record_size)` 创建表文件。
5. 把表元数据加入 `db_.tabs_`。
6. 打开表文件，放入 `fhs_`。
7. 调用 `flush_meta()` 写回 `db.meta`。

为什么列需要 offset：

一条记录在磁盘页中是连续字节，例如：

```text
grade(name char(20), id int, score float)

record layout:
+----------------------+-----+-------+
| name, 20 bytes       | id  | score |
+----------------------+-----+-------+
offset 0               20    24
```

查询、更新、投影时都要通过 offset 找字段。

### 4.2 `SmManager::open_db`

需要补的位置：

```text
rmdb/src/system/sm_manager.cpp
```

为什么必须实现：

主程序 `rmdb.cpp` 启动时会执行：

```cpp
if (!sm_manager->is_dir(db_name)) {
    sm_manager->create_db(db_name);
}
sm_manager->open_db(db_name);
```

如果 `open_db` 是空的，那么：

- 不会进入数据库目录。
- 不会读取 `db.meta`。
- `db_` 中没有表信息。
- `fhs_` 中没有表文件句柄。
- 后面 create/select/update/delete 都可能失败。

实现方式：

```cpp
void SmManager::open_db(const std::string& db_name) {
    if (!is_dir(db_name)) {
        throw DatabaseNotFoundError(db_name);
    }
    if (chdir(db_name.c_str()) < 0) {
        throw UnixError();
    }

    std::ifstream ifs(DB_META_NAME);
    if (!ifs.is_open()) {
        throw InternalError("Cannot open database meta file");
    }
    ifs >> db_;

    for (auto &entry : db_.tabs_) {
        auto &tab = entry.second;
        auto fh = rm_manager_->open_file(tab.name);
        disk_manager_->set_fd2pageno(fh->GetFd(), fh->get_file_hdr().num_pages);
        fhs_.emplace(tab.name, std::move(fh));

        for (auto &index : tab.indexes) {
            auto ih = ix_manager_->open_index(tab.name, index.cols);
            ihs_.emplace(ix_manager_->get_index_name(tab.name, index.cols), std::move(ih));
        }
    }
}
```

逐句解释：

```cpp
if (!is_dir(db_name)) {
    throw DatabaseNotFoundError(db_name);
}
```

数据库在 RMDB 中就是一个同名目录。如果目录不存在，说明数据库不存在。

```cpp
chdir(db_name.c_str())
```

进入数据库目录。这样后续打开表文件、写 `output.txt` 都会发生在数据库目录下。

```cpp
std::ifstream ifs(DB_META_NAME);
ifs >> db_;
```

读取数据库元数据。`DbMeta`、`TabMeta`、`ColMeta` 都重载了 `>>`，可以直接从文件恢复。

```cpp
auto fh = rm_manager_->open_file(tab.name);
fhs_.emplace(tab.name, std::move(fh));
```

打开每张表的数据文件，并保存文件句柄。执行器后面会通过：

```cpp
sm_manager_->fhs_.at(tab_name).get()
```

拿到表文件。

```cpp
disk_manager_->set_fd2pageno(fh->GetFd(), fh->get_file_hdr().num_pages);
```

恢复页号分配器状态。否则重新打开数据库后，`DiskManager::allocate_page` 可能又从 0 开始分配页号，覆盖已有页面。

### 4.3 `SmManager::close_db`

为什么必须实现：

服务端退出时会调用：

```cpp
sm_manager->close_db();
```

如果不关闭表文件：

- 文件头可能没有写回。
- 缓冲池中的脏页可能没有刷盘。
- 下次打开数据库时元数据可能不完整。

实现方式：

```cpp
void SmManager::close_db() {
    for (auto &entry : ihs_) {
        ix_manager_->close_index(entry.second.get());
    }
    ihs_.clear();

    for (auto &entry : fhs_) {
        rm_manager_->close_file(entry.second.get());
    }
    fhs_.clear();

    flush_meta();
    if (chdir("..") < 0) {
        throw UnixError();
    }
}
```

关键点：

- 先关索引，再关表文件。
- `rm_manager_->close_file` 会写回 `RmFileHdr` 并刷新缓冲池页面。
- `chdir("..")` 回到上级目录，避免进程一直停留在数据库目录中。

### 4.4 `SmManager::drop_table`

为什么必须实现：

测试点 1 会执行：

```sql
drop table t1;
show tables;
```

如果只删除文件，不删元数据，`show tables` 仍会显示旧表。

实现方式：

```cpp
void SmManager::drop_table(const std::string& tab_name, Context* context) {
    if (!db_.is_table(tab_name)) {
        throw TableNotFoundError(tab_name);
    }

    auto &tab = db_.get_table(tab_name);
    for (auto &index : tab.indexes) {
        auto ix_name = ix_manager_->get_index_name(tab_name, index.cols);
        auto ih = ihs_.find(ix_name);
        if (ih != ihs_.end()) {
            ix_manager_->close_index(ih->second.get());
            ihs_.erase(ih);
        }
        ix_manager_->destroy_index(tab_name, index.cols);
    }

    auto fh = fhs_.find(tab_name);
    if (fh != fhs_.end()) {
        rm_manager_->close_file(fh->second.get());
        fhs_.erase(fh);
    }

    rm_manager_->destroy_file(tab_name);
    db_.tabs_.erase(tab_name);
    flush_meta();
}
```

为什么要先关闭再删除：

`DiskManager::destroy_file` 会检查文件是否仍然打开。如果还在 `path2fd_` 中，删除会报 `FileNotClosedError`。

为什么要删除 `db_.tabs_`：

`show tables` 遍历的是：

```cpp
for (auto &entry : db_.tabs_)
```

所以删除表后必须同步删除内存元数据。

## 五、语义分析 Analyze 详解

文件：

```text
rmdb/src/analyze/analyze.cpp
```

语义分析的核心目的：

1. 检查 SQL 中的表是否存在。
2. 检查 SQL 中的列是否存在。
3. 补全省略的表名。
4. 检查条件左右两边类型是否兼容。
5. 把 AST 中的值转换成执行器能用的 `Value`。
6. 把 where 条件转换成 `Condition`。
7. 把 update set 子句转换成 `SetClause`。

### 5.1 `Analyze::do_analyze`

入口函数：

```cpp
std::shared_ptr<Query> Analyze::do_analyze(std::shared_ptr<ast::TreeNode> parse)
```

这个函数根据 AST 类型分支处理。

### 5.2 SelectStmt 分支怎么写

对应代码逻辑：

```cpp
if (auto x = std::dynamic_pointer_cast<ast::SelectStmt>(parse)) {
    query->tables = std::move(x->tabs);
    ...
}
```

第一步：保存并检查表名。

```cpp
query->tables = std::move(x->tabs);
for (auto &tab_name : query->tables) {
    if (!sm_manager_->db_.is_table(tab_name)) {
        throw TableNotFoundError(tab_name);
    }
}
```

为什么要检查：

- 如果 `select * from unknown;` 不检查，后续 `get_all_cols` 会访问不存在的表。
- 语义错误应该在 Analyze 阶段报出。

第二步：处理 select 列表。

```cpp
for (auto &sv_sel_col : x->cols) {
    TabCol sel_col = {
        .tab_name = sv_sel_col->tab_name,
        .col_name = sv_sel_col->col_name
    };
    query->cols.push_back(sel_col);
}
```

AST 中的列是 `ast::Col`，执行计划中使用的是 `TabCol`。这里完成格式转换。

第三步：收集所有参与表的列。

```cpp
std::vector<ColMeta> all_cols;
get_all_cols(query->tables, all_cols);
```

`all_cols` 用来：

- 展开 `select *`
- 检查列名
- 对省略表名的列做表名推断

第四步：处理 `select *`。

```cpp
if (query->cols.empty()) {
    for (auto &col : all_cols) {
        TabCol sel_col = {.tab_name = col.tab_name, .col_name = col.name};
        query->cols.push_back(sel_col);
    }
}
```

在 Parser 中，`select *` 会让 `x->cols` 为空。因此 Analyze 需要把它展开成所有列。

为什么在 Analyze 展开：

- Planner 和 ProjectionExecutor 不需要知道用户写的是 `*` 还是列名列表。
- 后续统一按照 `query->cols` 做投影。

第五步：处理指定列。

```cpp
for (auto &sel_col : query->cols) {
    sel_col = check_column(all_cols, sel_col);
}
```

`check_column` 会补全表名。例如：

```sql
select name from grade;
```

会把：

```text
name
```

变成：

```text
grade.name
```

第六步：处理 where。

```cpp
get_clause(x->conds, query->conds);
check_clause(query->tables, query->conds);
```

`get_clause` 负责 AST 到 `Condition` 的结构转换。

`check_clause` 负责列名检查、类型检查、常量 raw 初始化。

### 5.3 InsertStmt 分支怎么写

对应 SQL：

```sql
insert into grade values ('Data Structure', 1, 90.5);
```

实现逻辑：

```cpp
} else if (auto x = std::dynamic_pointer_cast<ast::InsertStmt>(parse)) {
    if (!sm_manager_->db_.is_table(x->tab_name)) {
        throw TableNotFoundError(x->tab_name);
    }
    for (auto &sv_val : x->vals) {
        query->values.push_back(convert_sv_value(sv_val));
    }
}
```

为什么这里只转换 value，不检查列数：

- 列数检查放在 `InsertExecutor` 构造函数中：

```cpp
if (values.size() != tab_.cols.size()) {
    throw InvalidValueCountError();
}
```

为什么要转换 value：

AST 中的值有这些类型：

```cpp
ast::IntLit
ast::FloatLit
ast::StringLit
```

执行器中统一使用：

```cpp
Value
```

### 5.4 DeleteStmt 分支怎么写

对应 SQL：

```sql
delete from grade where score > 90;
```

实现逻辑：

```cpp
} else if (auto x = std::dynamic_pointer_cast<ast::DeleteStmt>(parse)) {
    if (!sm_manager_->db_.is_table(x->tab_name)) {
        throw TableNotFoundError(x->tab_name);
    }
    get_clause(x->conds, query->conds);
    check_clause({x->tab_name}, query->conds);
}
```

为什么 `check_clause` 传 `{x->tab_name}`：

delete 只作用于一张表。where 中省略表名时，只能从这张表中推断。

### 5.5 UpdateStmt 分支怎么写

对应 SQL：

```sql
update grade set name = 'Error', id = -1, score = 0
where name = 'Error name' and score >= 90;
```

实现逻辑分两部分：

1. 分析 set 子句。
2. 分析 where 子句。

代码：

```cpp
} else if (auto x = std::dynamic_pointer_cast<ast::UpdateStmt>(parse)) {
    if (!sm_manager_->db_.is_table(x->tab_name)) {
        throw TableNotFoundError(x->tab_name);
    }
    TabMeta &tab = sm_manager_->db_.get_table(x->tab_name);

    for (auto &sv_set_clause : x->set_clauses) {
        auto col = tab.get_col(sv_set_clause->col_name);
        SetClause set_clause;
        set_clause.lhs = {.tab_name = x->tab_name, .col_name = sv_set_clause->col_name};
        set_clause.rhs = convert_sv_value(sv_set_clause->val);
        ...
        query->set_clauses.push_back(set_clause);
    }

    get_clause(x->conds, query->conds);
    check_clause({x->tab_name}, query->conds);
}
```

为什么 update 要提前分析 set：

- 执行器只负责执行，不应该再去理解 AST。
- set 右值要提前变成 raw 字节，方便写入记录。

### 5.6 update 中 int 到 float 的提升

题目样例中有：

```sql
update grade set score = 90 where name = 'Calculus';
```

`score` 是 float，但 `90` 是 int 字面量。

如果严格要求类型完全相等，会报：

```text
Incompatible type error: lhs FLOAT, rhs INT
```

所以需要：

```cpp
if (col->type == TYPE_FLOAT && set_clause.rhs.type == TYPE_INT) {
    set_clause.rhs.set_float(static_cast<float>(set_clause.rhs.int_val));
}
```

为什么只做 int 到 float：

- 这是安全的数值提升。
- 不做 string 和数字之间的隐式转换。
- 不做 float 到 int，避免精度丢失。

### 5.7 `check_column` 怎么写

函数：

```cpp
TabCol Analyze::check_column(const std::vector<ColMeta> &all_cols, TabCol target)
```

分两种情况。

#### 情况 1：没有表名

例如：

```sql
select id from grade;
```

`target.tab_name` 为空。

实现：

```cpp
if (target.tab_name.empty()) {
    std::string tab_name;
    for (auto &col : all_cols) {
        if (col.name == target.col_name) {
            if (!tab_name.empty()) {
                throw AmbiguousColumnError(target.col_name);
            }
            tab_name = col.tab_name;
        }
    }
    if (tab_name.empty()) {
        throw ColumnNotFoundError(target.col_name);
    }
    target.tab_name = tab_name;
}
```

为什么要检查歧义：

例如：

```sql
select id from t, d;
```

如果 `t` 和 `d` 都有 `id`，系统无法知道用户要哪一个，必须报错。

#### 情况 2：写了表名

例如：

```sql
select t.id from t, d;
```

实现：

```cpp
bool found = false;
for (auto &col : all_cols) {
    if (col.tab_name == target.tab_name && col.name == target.col_name) {
        found = true;
        break;
    }
}
if (!found) {
    throw ColumnNotFoundError(target.tab_name + "." + target.col_name);
}
```

为什么不能只检查列名：

`t.id` 必须要求 `t` 表中有 `id`，不能因为别的表有 `id` 就通过。

### 5.8 `get_all_cols` 怎么写

函数：

```cpp
void Analyze::get_all_cols(
    const std::vector<std::string> &tab_names,
    std::vector<ColMeta> &all_cols)
```

实现：

```cpp
for (auto &sel_tab_name : tab_names) {
    const auto &sel_tab_cols = sm_manager_->db_.get_table(sel_tab_name).cols;
    all_cols.insert(all_cols.end(), sel_tab_cols.begin(), sel_tab_cols.end());
}
```

作用：

- 把所有参与查询的表的列拼成一个数组。
- 保持表在 SQL 中出现的顺序。
- `select *` 的列顺序就来自这里。

### 5.9 `get_clause` 怎么写

函数：

```cpp
void Analyze::get_clause(
    const std::vector<std::shared_ptr<ast::BinaryExpr>> &sv_conds,
    std::vector<Condition> &conds)
```

AST 中 where 条件形如：

```cpp
ast::BinaryExpr {
    lhs: ast::Col
    op:  ast::SvCompOp
    rhs: ast::Expr
}
```

执行器中使用：

```cpp
struct Condition {
    TabCol lhs_col;
    CompOp op;
    bool is_rhs_val;
    TabCol rhs_col;
    Value rhs_val;
};
```

实现步骤：

1. 复制左列。
2. 转换比较符。
3. 判断右侧是常量还是列。
4. 如果右侧是常量，填 `rhs_val`。
5. 如果右侧是列，填 `rhs_col`。

为什么需要 `is_rhs_val`：

where 支持两类条件：

```sql
score > 90
t.id = d.id
```

第一种右侧是值，第二种右侧是列。执行器比较时需要区分。

### 5.10 `check_clause` 怎么写

函数：

```cpp
void Analyze::check_clause(
    const std::vector<std::string> &tab_names,
    std::vector<Condition> &conds)
```

实现步骤：

1. 收集所有表的列。
2. 对每个条件：
   - 补全左列表名。
   - 如果右侧是列，补全右列表名。
   - 找到左右列类型。
   - 检查类型兼容。
   - 如果右侧是常量，生成 raw 字节。

为什么常量要调用 `init_raw`：

执行器面对的是记录中的二进制数据。比如 int 在记录中是 4 字节，float 也是 4 字节。条件右侧常量也必须变成同样格式，才能用统一逻辑比较。

### 5.11 `convert_sv_value` 怎么写

函数：

```cpp
Value Analyze::convert_sv_value(const std::shared_ptr<ast::Value> &sv_val)
```

实现：

```cpp
if (auto int_lit = std::dynamic_pointer_cast<ast::IntLit>(sv_val)) {
    val.set_int(int_lit->val);
} else if (auto float_lit = std::dynamic_pointer_cast<ast::FloatLit>(sv_val)) {
    val.set_float(float_lit->val);
} else if (auto str_lit = std::dynamic_pointer_cast<ast::StringLit>(sv_val)) {
    val.set_str(str_lit->val);
} else {
    throw InternalError("Unexpected sv value type");
}
```

为什么不在这里直接 `init_raw`：

- string 的 raw 长度取决于列定义，例如 `char(4)` 或 `char(20)`。
- int/float 长度固定，但为了统一，也在知道目标列后再初始化。

## 六、执行器通用条件判断详解

文件：

```text
rmdb/src/execution/executor_abstract.h
```

题目二中，多个执行器都需要判断条件：

- `SeqScanExecutor` 判断单表 where。
- `NestedLoopJoinExecutor` 判断连接条件。
- 后续索引扫描也可以复用。

所以在 `AbstractExecutor` 中加入通用函数。

### 6.1 `compare_raw`

作用：比较两个字段的原始字节。

实现：

```cpp
static int compare_raw(const char *lhs, const char *rhs, ColType type, int len) {
    if (type == TYPE_INT) {
        int lhs_val = *reinterpret_cast<const int *>(lhs);
        int rhs_val = *reinterpret_cast<const int *>(rhs);
        return (lhs_val > rhs_val) - (lhs_val < rhs_val);
    }
    if (type == TYPE_FLOAT) {
        float lhs_val = *reinterpret_cast<const float *>(lhs);
        float rhs_val = *reinterpret_cast<const float *>(rhs);
        return (lhs_val > rhs_val) - (lhs_val < rhs_val);
    }
    return strncmp(lhs, rhs, len);
}
```

为什么 int/float 不能直接 `memcmp`：

- int 和 float 的二进制字节顺序不能直接代表数值大小。
- 例如负数的二进制表示用补码，`memcmp` 会得到错误顺序。

为什么 string 可以 `strncmp`：

- char(n) 字段以字符字节存储。
- SQL 样例中字符串比较按字典序即可满足。

### 6.2 `compare_result`

作用：把比较结果映射到 SQL 操作符。

```cpp
static bool compare_result(int cmp, CompOp op) {
    switch (op) {
        case OP_EQ: return cmp == 0;
        case OP_NE: return cmp != 0;
        case OP_LT: return cmp < 0;
        case OP_GT: return cmp > 0;
        case OP_LE: return cmp <= 0;
        case OP_GE: return cmp >= 0;
    }
    return false;
}
```

为什么要拆成两个函数：

- `compare_raw` 只负责“大小关系”。
- `compare_result` 只负责“操作符判断”。
- 这样逻辑清晰，也方便多个执行器复用。

### 6.3 `eval_cond`

作用：判断一条记录是否满足一个条件。

步骤：

1. 根据 `cond.lhs_col` 找左列元数据。
2. 从记录中取左列地址：

```cpp
const char *lhs = rec->data + lhs_col->offset;
```

3. 判断右侧是值还是列。
4. 如果右侧是值，用 `rhs_val.raw->data`。
5. 如果右侧是列，根据右列 offset 从同一条记录中取右值。
6. 调用 `compare_raw` 和 `compare_result`。

为什么连接条件也能用这个函数：

NestedLoopJoin 会把左右记录拼成一条 joined record，列元数据也拼起来并调整 offset。因此：

```sql
t.id = d.id
```

可以在 joined record 上像普通条件一样判断。

### 6.4 `eval_conds`

作用：判断一条记录是否满足所有条件。

实现：

```cpp
for (auto &cond : conds) {
    if (!eval_cond(rec_cols, rec, cond)) {
        return false;
    }
}
return true;
```

为什么是 AND：

题目 SQL where 子句只要求：

```sql
condition and condition and ...
```

不涉及 OR。

## 七、SeqScanExecutor 详解

文件：

```text
rmdb/src/execution/executor_seq_scan.h
```

顺序扫描执行器负责：

- 遍历表中所有有效记录。
- 跳过不满足 where 条件的记录。
- 暴露当前记录的 `Rid`，供 update/delete 使用。
- 返回当前记录内容，供 select/projection/join 使用。

### 7.1 构造函数

构造函数里要准备：

```cpp
tab_name_ = std::move(tab_name);
conds_ = std::move(conds);
TabMeta &tab = sm_manager_->db_.get_table(tab_name_);
fh_ = sm_manager_->fhs_.at(tab_name_).get();
cols_ = tab.cols;
len_ = cols_.back().offset + cols_.back().len;
fed_conds_ = conds_;
```

解释：

- `fh_` 是表文件句柄，用来读记录。
- `cols_` 是输出记录的列元数据。
- `len_` 是一条完整记录的长度。
- `fed_conds_` 是需要判断的 where 条件。

为什么 `len_` 用最后一列：

列是按 offset 顺序排列的，最后一列的：

```cpp
offset + len
```

就是整条记录长度。

### 7.2 `beginTuple`

实现逻辑：

```cpp
scan_ = std::make_unique<RmScan>(fh_);
while (!scan_->is_end()) {
    rid_ = scan_->rid();
    auto rec = fh_->get_record(rid_, context_);
    if (eval_conds(cols_, rec.get(), fed_conds_)) {
        return;
    }
    scan_->next();
}
```

为什么要循环：

`RmScan` 只负责找到有效记录，不负责 where 条件。所以 `SeqScanExecutor` 要继续跳过不满足 where 的记录。

### 7.3 `nextTuple`

实现逻辑：

```cpp
scan_->next();
while (!scan_->is_end()) {
    rid_ = scan_->rid();
    auto rec = fh_->get_record(rid_, context_);
    if (eval_conds(cols_, rec.get(), fed_conds_)) {
        return;
    }
    scan_->next();
}
```

为什么先 `scan_->next()`：

当前记录已经被上层消费，所以下一次查找要从后一条记录开始。

### 7.4 `Next`

实现：

```cpp
if (scan_ == nullptr || scan_->is_end()) {
    return nullptr;
}
rid_ = scan_->rid();
return fh_->get_record(rid_, context_);
```

为什么 `Next` 不推进扫描器：

框架中的调用方式是：

```cpp
for (executor->beginTuple(); !executor->is_end(); executor->nextTuple()) {
    auto rec = executor->Next();
}
```

也就是说：

- `beginTuple` 定位第一条。
- `Next` 读取当前条。
- `nextTuple` 移动到下一条。

如果 `Next` 自己推进，会跳记录。

### 7.5 `rid`

```cpp
Rid &rid() override { return rid_; }
```

为什么重要：

Portal 在 update/delete 前会扫描满足条件的记录：

```cpp
for (scan->beginTuple(); !scan->is_end(); scan->nextTuple()) {
    rids.push_back(scan->rid());
}
```

如果 `rid_` 不正确，update/delete 会改错记录。

## 八、ProjectionExecutor 详解

文件：

```text
rmdb/src/execution/executor_projection.h
```

ProjectionExecutor 负责 select 输出列。

例如表定义为：

```sql
create table grade (name char(20), id int, score float);
```

原记录顺序：

```text
name, id, score
```

SQL：

```sql
select score,name,id from grade;
```

输出顺序：

```text
score, name, id
```

这就必须靠 ProjectionExecutor 重排字段。

### 8.1 构造函数怎么写

构造函数：

```cpp
ProjectionExecutor(
    std::unique_ptr<AbstractExecutor> prev,
    const std::vector<TabCol> &sel_cols)
```

关键逻辑：

```cpp
size_t curr_offset = 0;
auto &prev_cols = prev_->cols();
for (auto &sel_col : sel_cols) {
    auto pos = get_col(prev_cols, sel_col);
    sel_idxs_.push_back(pos - prev_cols.begin());
    auto col = *pos;
    col.offset = curr_offset;
    curr_offset += col.len;
    cols_.push_back(col);
}
len_ = curr_offset;
```

逐句解释：

```cpp
auto pos = get_col(prev_cols, sel_col);
```

在子执行器输出列中找到目标列。

```cpp
sel_idxs_.push_back(pos - prev_cols.begin());
```

记录目标列在子记录中的下标，方便 `Next` 快速拷贝。

```cpp
col.offset = curr_offset;
```

投影后的新记录是重新排列的，所以 offset 要从 0 重新计算。

### 8.2 `beginTuple` 和 `nextTuple`

实现：

```cpp
void beginTuple() override { prev_->beginTuple(); }
void nextTuple() override { prev_->nextTuple(); }
```

为什么直接转发：

Projection 不决定扫描顺序，它只是改造子执行器当前输出的记录。

### 8.3 `Next`

实现步骤：

1. 从子执行器取当前完整记录。
2. 创建新的 `RmRecord`。
3. 按 `sel_idxs_` 找到每个目标字段。
4. 把字段拷贝到新记录的对应 offset。
5. 返回新记录。

代码：

```cpp
auto prev_rec = prev_->Next();
auto rec = std::make_unique<RmRecord>(len_);
auto &prev_cols = prev_->cols();
for (size_t i = 0; i < sel_idxs_.size(); ++i) {
    auto &src_col = prev_cols[sel_idxs_[i]];
    memcpy(rec->data + cols_[i].offset,
           prev_rec->data + src_col.offset,
           src_col.len);
}
return rec;
```

为什么必须创建新记录：

- 上层 `QlManager::select_from` 会根据 `executorTreeRoot->cols()` 输出字段。
- 如果投影后不创建新记录，字段 offset 和数据布局会不一致。

## 九、NestedLoopJoinExecutor 详解

文件：

```text
rmdb/src/execution/executor_nestedloop_join.h
```

NestedLoopJoinExecutor 负责多表连接。

### 9.1 Join 输出记录长什么样

假设：

```text
t(id int, t_name char(3))
d(d_name char(5), id int)
```

一条 t 记录：

```text
| 1 | aaa |
```

一条 d 记录：

```text
| 12345 | 1 |
```

join 后记录：

```text
| 1 | aaa | 12345 | 1 |
```

也就是把左记录字节和右记录字节拼接。

### 9.2 构造函数怎么写

构造函数核心：

```cpp
left_ = std::move(left);
right_ = std::move(right);
len_ = left_->tupleLen() + right_->tupleLen();
cols_ = left_->cols();
auto right_cols = right_->cols();
for (auto &col : right_cols) {
    col.offset += left_->tupleLen();
}
cols_.insert(cols_.end(), right_cols.begin(), right_cols.end());
fed_conds_ = std::move(conds);
```

为什么右表列 offset 要加 `left_->tupleLen()`：

右表字段在 joined record 中排在左表记录之后。

例如：

```text
left len = 7
right d_name 原 offset = 0
join 后 d_name offset = 7 + 0
```

如果不调整 offset，后续投影 `d_name` 会从 joined record 的开头取数据，取到的是左表字段。

### 9.3 为什么物化右表

实现中把右子执行器全部读入：

```cpp
right_records_.clear();
right_->beginTuple();
for (; !right_->is_end(); right_->nextTuple()) {
    right_records_.push_back(right_->Next());
}
```

为什么这么做：

- 嵌套循环连接需要对每条左记录重复遍历右表。
- 右执行器不一定支持“无成本重置”。
- 物化后可以反复遍历右侧记录，逻辑简单稳定。

题目二数据量较小，这样实现足够通过测试。

### 9.4 `beginTuple`

实现逻辑：

1. 物化右表。
2. 定位左表第一条记录。
3. 设置右侧遍历位置。
4. 调用 `advance_to_match()` 找第一条满足连接条件的组合。

关键代码：

```cpp
left_->beginTuple();
if (left_->is_end()) {
    isend = true;
    return;
}
left_rec_ = left_->Next();
right_pos_ = static_cast<int>(right_records_.size()) - 1;
advance_to_match();
```

为什么右表从最后一条开始：

题目样例中 `select * from t, d` 的笛卡尔积输出顺序是：

```text
t1 × d2
t1 × d1
t2 × d2
t2 × d1
t3 × d2
t3 × d1
```

而 `RmScan` 读取 d 表的自然顺序是：

```text
d1, d2
```

为了匹配样例，右表按反向遍历。

### 9.5 `advance_to_match`

这是连接执行器的核心函数。

逻辑：

```text
while true:
    while 右表还有记录:
        拼接 left_rec 和 right_rec
        如果满足连接条件:
            停在这个组合
            return
        移动到下一条右记录

    左表移动到下一条
    如果左表结束:
        isend = true
        return
    右表重新从末尾开始
```

为什么条件为空也能工作：

`eval_conds` 对空条件数组返回 true，因此：

```sql
select * from t, d;
```

会输出所有组合，也就是笛卡尔积。

### 9.6 `Next`

实现：

```cpp
auto rec = std::make_unique<RmRecord>(len_);
memcpy(rec->data, left_rec_->data, left_->tupleLen());
memcpy(rec->data + left_->tupleLen(), right_rec_->data, right_->tupleLen());
return rec;
```

为什么不是直接返回左右记录：

ProjectionExecutor 和 QlManager 期望每个执行器返回一条完整 `RmRecord`。Join 的输出本身也是一条新记录，所以必须拼接成新的 `RmRecord`。

## 十、InsertExecutor 详解

文件：

```text
rmdb/src/execution/executor_insert.h
```

InsertExecutor 负责执行：

```sql
insert into grade values ('Data Structure', 1, 90.5);
```

### 10.1 构造函数

构造函数做：

```cpp
tab_ = sm_manager_->db_.get_table(tab_name);
values_ = values;
tab_name_ = tab_name;
if (values.size() != tab_.cols.size()) {
    throw InvalidValueCountError();
}
fh_ = sm_manager_->fhs_.at(tab_name).get();
```

为什么检查 value 数量：

题目只支持：

```sql
insert into table values (...)
```

没有指定列名，因此 values 数量必须等于表列数。

### 10.2 `Next`

实现步骤：

1. 创建一条空记录：

```cpp
RmRecord rec(fh_->get_file_hdr().record_size);
```

2. 遍历所有列和 value。
3. 检查类型。
4. 把 value 初始化为 raw。
5. 拷贝到记录对应 offset。
6. 调用 `fh_->insert_record`。
7. 如果有索引，同步插入索引项。

关键代码：

```cpp
for (size_t i = 0; i < values_.size(); i++) {
    auto &col = tab_.cols[i];
    auto &val = values_[i];
    if (col.type == TYPE_FLOAT && val.type == TYPE_INT) {
        val.set_float(static_cast<float>(val.int_val));
    }
    if (col.type != val.type) {
        throw IncompatibleTypeError(coltype2str(col.type), coltype2str(val.type));
    }
    val.init_raw(col.len);
    memcpy(rec.data + col.offset, val.raw->data, col.len);
}
rid_ = fh_->insert_record(rec.data, context_);
```

为什么按表列顺序写：

`insert into table values (...)` 的语义就是 values 按表定义列顺序对应。

## 十一、DeleteExecutor 详解

文件：

```text
rmdb/src/execution/executor_delete.h
```

DeleteExecutor 不自己扫描表。Portal 已经先扫描并收集了所有要删除的 `Rid`。

Portal 中的逻辑：

```cpp
std::unique_ptr<AbstractExecutor> scan = convert_plan_executor(x->subplan_, context);
std::vector<Rid> rids;
for (scan->beginTuple(); !scan->is_end(); scan->nextTuple()) {
    rids.push_back(scan->rid());
}
```

为什么要先收集：

如果边扫描边删除：

- bitmap 会改变。
- 当前页记录数量会改变。
- 扫描器可能跳过记录或重复访问。

先收集 `Rid`，再统一删除，更安全。

### 11.1 `Next`

实现：

```cpp
for (auto &rid : rids_) {
    auto rec = fh_->get_record(rid, context_);
    ...
    fh_->delete_record(rid, context_);
}
return nullptr;
```

如果表上有索引，删除记录前要删除索引项：

```cpp
for (auto &index : tab_.indexes) {
    auto ih = sm_manager_->ihs_.at(...).get();
    std::vector<char> key(index.col_tot_len);
    ...
    ih->delete_entry(key.data(), context_->txn_);
}
```

为什么先删索引再删记录：

索引 key 要从旧记录中取。如果先删记录，就读不到旧记录内容。

## 十二、UpdateExecutor 详解

文件：

```text
rmdb/src/execution/executor_update.h
```

UpdateExecutor 和 DeleteExecutor 类似，也由 Portal 先扫描满足 where 条件的 `Rid`。

### 12.1 为什么 update 要先读旧记录

例如：

```sql
update grade set score = 90 where name = 'Calculus';
```

只修改 `score`，但 `name` 和 `id` 必须保持原值。

所以执行流程必须是：

1. 读旧记录。
2. 拷贝旧记录。
3. 在拷贝上修改 set 指定字段。
4. 写回新记录。

### 12.2 `Next`

核心代码：

```cpp
auto old_rec = fh_->get_record(rid, context_);
RmRecord new_rec(fh_->get_file_hdr().record_size);
memcpy(new_rec.data, old_rec->data, fh_->get_file_hdr().record_size);
```

这一步得到完整新记录的初始版本。

然后处理 set 子句：

```cpp
for (auto &set_clause : set_clauses_) {
    auto col = tab_.get_col(set_clause.lhs.col_name);
    if (col->type != set_clause.rhs.type) {
        throw IncompatibleTypeError(...);
    }
    if (set_clause.rhs.raw == nullptr) {
        set_clause.rhs.init_raw(col->len);
    }
    memcpy(new_rec.data + col->offset, set_clause.rhs.raw->data, col->len);
}
```

为什么判断 `raw == nullptr`：

Analyze 阶段已经对 set 右值做过 `init_raw`。这里加判断是为了避免重复初始化导致断言失败。

最后写回：

```cpp
fh_->update_record(rid, new_rec.data, context_);
```

### 12.3 update 中索引维护

如果表上有索引：

1. 从旧记录生成旧 key。
2. 从新记录生成新 key。
3. 删除旧 key。
4. 插入新 key。

这样索引和表数据保持一致。

虽然题目二测试不依赖索引，但保留这部分逻辑可以避免后续题目出问题。

## 十三、Planner 详解

文件：

```text
rmdb/src/optimizer/planner.cpp
```

### 13.1 `do_planner`

`do_planner` 根据 AST 类型生成不同 Plan。

DDL：

```cpp
CreateTable -> DDLPlan(T_CreateTable)
DropTable   -> DDLPlan(T_DropTable)
```

DML：

```cpp
InsertStmt -> DMLPlan(T_Insert)
DeleteStmt -> DMLPlan(T_Delete)
UpdateStmt -> DMLPlan(T_Update)
```

DQL：

```cpp
SelectStmt -> DMLPlan(T_select, ProjectionPlan(...))
```

### 13.2 `generate_select_plan`

实现逻辑：

```cpp
query = logical_optimization(std::move(query), context);
auto sel_cols = query->cols;
std::shared_ptr<Plan> plannerRoot = physical_optimization(query, context);
plannerRoot = std::make_shared<ProjectionPlan>(
    T_Projection,
    std::move(plannerRoot),
    std::move(sel_cols)
);
return plannerRoot;
```

为什么最外层一定套 ProjectionPlan：

- `select *` 时，ProjectionPlan 输出所有列。
- `select score,name,id` 时，ProjectionPlan 重排列。
- 这样 `QlManager::select_from` 可以统一从根执行器取记录和列元数据。

### 13.3 `make_one_rel`

这是 select 查询计划生成的核心。

#### 单表查询

如果只有一张表：

```cpp
return table_scan_executors[0];
```

表扫描计划来自：

```cpp
std::make_shared<ScanPlan>(
    T_SeqScan,
    sm_manager_,
    tables[i],
    curr_conds,
    index_col_names
);
```

为什么用 SeqScan：

题目二测试不要求索引查询，顺序扫描可以覆盖所有单表 where 查询。

#### 多表查询

多表查询要生成 JoinPlan。

如果 where 中有列和列之间的条件，例如：

```sql
where t.id = d.id
```

Planner 会把这个条件作为 join condition，生成：

```text
JoinPlan(T_NestLoop, Scan(t), Scan(d), t.id = d.id)
```

如果没有连接条件：

```sql
select * from t, d;
```

就生成没有条件的 JoinPlan：

```text
JoinPlan(T_NestLoop, Scan(t), Scan(d), empty conds)
```

空条件在执行器中表示笛卡尔积。

### 13.4 为什么调整剩余表连接方向

原始逻辑中，剩余表连接时可能生成：

```text
JoinPlan(Scan(d), Scan(t))
```

这会导致列顺序或行顺序和题目样例不一致。

因此改成：

```cpp
table_join_executors = std::make_shared<JoinPlan>(
    T_NestLoop,
    std::move(table_join_executors),
    std::move(table_scan_executors[i]),
    std::vector<Condition>()
);
```

这样对于：

```sql
select * from t, d;
```

join 左侧是 `t`，右侧是 `d`，列顺序就是：

```text
t 的列 + d 的列
```

符合题目输出：

```text
| id | t_name | d_name | id |
```

## 十四、Portal 如何衔接 Plan 和 Executor

文件：

```text
rmdb/src/portal.h
```

虽然本题主要不改 Portal，但必须理解它。

### 14.1 select

对于 select：

```cpp
std::shared_ptr<ProjectionPlan> p =
    std::dynamic_pointer_cast<ProjectionPlan>(x->subplan_);
std::unique_ptr<AbstractExecutor> root =
    convert_plan_executor(p, context);
return std::make_shared<PortalStmt>(
    PORTAL_ONE_SELECT,
    std::move(p->sel_cols_),
    std::move(root),
    plan
);
```

之后：

```cpp
ql->select_from(std::move(portal->root), std::move(portal->sel_cols), context);
```

### 14.2 update/delete

update/delete 的特殊点是先扫描 `Rid`：

```cpp
std::unique_ptr<AbstractExecutor> scan = convert_plan_executor(x->subplan_, context);
std::vector<Rid> rids;
for (scan->beginTuple(); !scan->is_end(); scan->nextTuple()) {
    rids.push_back(scan->rid());
}
```

然后构造：

```cpp
UpdateExecutor(..., rids, context)
DeleteExecutor(..., rids, context)
```

这就是为什么 `SeqScanExecutor::rid()` 必须正确。

## 十五、QlManager 输出逻辑

文件：

```text
rmdb/src/execution/execution_manager.cpp
```

题目要求输出写入数据库目录下的 `output.txt`。

### 15.1 `show_tables`

`SmManager::show_tables` 中写：

```cpp
outfile.open("output.txt", std::ios::out | std::ios::app);
outfile << "| Tables |\n";
...
```

因为 `open_db` 后已经 `chdir` 到数据库目录，所以这里的 `output.txt` 正是：


### 15.2 `select_from`

`QlManager::select_from` 做两件事：

1. 输出到客户端 buffer。
2. 追加写入 `output.txt`。

核心循环：

```cpp
for (executorTreeRoot->beginTuple();
     !executorTreeRoot->is_end();
     executorTreeRoot->nextTuple()) {
    auto Tuple = executorTreeRoot->Next();
    ...
    outfile << "|";
    for (...) {
        outfile << " " << columns[i] << " |";
    }
    outfile << "\n";
}
```

为什么执行器必须实现 `beginTuple/is_end/nextTuple/Next`：

`select_from` 完全依赖这个迭代协议。如果任何一个执行器没有正确实现，select 就没有输出。

## 十六、事务管理最小实现

文件：

```text
rmdb/src/transaction/transaction_manager.cpp
```

题目二不要求完整事务，但主程序每条 SQL 都会：

```cpp
SetTransaction(&txn_id, context);
...
txn_manager->commit(context->txn_, context->log_mgr_);
```

原框架中：

```cpp
TransactionManager::begin(...) {
    return nullptr;
}
```

这会导致：

```cpp
context->txn_->get_txn_mode()
```

直接段错误。

### 16.1 `begin`

实现：

```cpp
Transaction *TransactionManager::begin(Transaction *txn, LogManager *log_manager) {
    (void)log_manager;
    if (txn == nullptr) {
        txn = new Transaction(next_txn_id_++);
    }
    txn->set_state(TransactionState::GROWING);
    txn->set_start_ts(next_timestamp_++);
    std::unique_lock<std::mutex> lock(latch_);
    txn_map[txn->get_transaction_id()] = txn;
    return txn;
}
```

为什么要加入 `txn_map`：

后续 `commit`、`rollback` 可能通过事务 ID 调用：

```cpp
txn_mgr_->get_transaction(*txn_id)
```

如果没加入 map，会触发断言。

### 16.2 `commit`

实现：

```cpp
void TransactionManager::commit(Transaction *txn, LogManager *log_manager) {
    (void)log_manager;
    if (txn == nullptr) {
        return;
    }
    txn->set_state(TransactionState::COMMITTED);
}
```

为什么只改状态：

题目二没有并发控制、日志恢复要求。只要让主流程不崩溃即可。

### 16.3 `abort`

实现：

```cpp
void TransactionManager::abort(Transaction *txn, LogManager *log_manager) {
    (void)log_manager;
    if (txn == nullptr) {
        return;
    }
    txn->set_state(TransactionState::ABORTED);
}
```

## 十九、常见错误和原因

### 19.1 服务端第一条 SQL 就段错误

原因：

```cpp
TransactionManager::begin
```

返回了 `nullptr`。

解决：

实现最小事务 begin/commit/abort。

### 19.2 `show tables` 没有输出或输出旧表

原因：

- `create_table` 后没有更新 `db_.tabs_`。
- `drop_table` 后没有删除 `db_.tabs_`。
- 没有写 `output.txt`。

### 19.3 `select score where score > 90` 报类型错误

原因：

`90` 被解析为 int，`score` 是 float。

解决：

Analyze 中对 float 列和 int 常量做 int 到 float 提升。

### 19.4 update 后其他列变空

原因：

UpdateExecutor 只写了 set 字段，没有先拷贝旧记录。

解决：

先：

```cpp
memcpy(new_rec.data, old_rec->data, record_size);
```

再覆盖 set 字段。

### 19.5 连接查询列值错位

原因：

右表列元数据 offset 没有加左记录长度。

解决：

```cpp
for (auto &col : right_cols) {
    col.offset += left_->tupleLen();
}
```

### 19.6 `select * from t,d` 列顺序不对

原因：

Planner 构造 join 树时把表顺序反了。

解决：

保证 join 左侧是 SQL 中靠前的表，右侧是后出现的表。

## 二十、实现原则总结

1. Analyze 负责检查语义，不让非法表名、列名、类型进入执行器。
2. Planner 负责生成树形计划，不直接执行。
3. Portal 负责把 Plan 转成 Executor。
4. Executor 负责迭代式产生记录。
5. SeqScan 负责 where 过滤。
6. Projection 负责列顺序和列裁剪。
7. Join 负责拼接左右记录并判断连接条件。
8. update/delete 不边扫描边修改，先收集 `Rid` 再执行。
9. 输出写入数据库目录下的 `output.txt`。
10. 题目二不需要完整事务，但必须有最小事务对象保证主流程不崩溃。
