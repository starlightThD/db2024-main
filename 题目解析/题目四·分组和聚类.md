# 题目四·分组和聚类（完整修改记录）

## 1. 目标与范围
本次目标是在 RMDB 中打通 `GROUP BY`、聚合函数与 `HAVING` 的最小可运行链路，并满足评测平台对健壮性（非法 SQL 输出 `failure`）的要求。

本次支持的核心 SQL 能力：
1. 聚合函数：`COUNT(*)`、`COUNT(col)`、`MAX(col)`、`MIN(col)`、`SUM(col)`、`AVG(col)`
2. 分组：`GROUP BY col[, ...]`
3. 分组过滤：`HAVING`，支持 `AND` / `OR` 组合（按 `AND` 优先于 `OR`）
4. 列别名：`expr AS alias`

---

## 2. 实现链路总览（从词法到执行）

### 2.1 词法分析（lex）
文件：`rmdb/src/parser/lex.l`

新增关键字识别：
1. `GROUP` / `HAVING`
2. `COUNT` / `SUM` / `AVG` / `MIN` / `MAX`
3. `AS`
4. `OR`

修复点：
1. 关键字规则的模式与动作之间统一空格，避免 `flex` 报“不能识别的规则”。
2. 单行注释规则改为 `"--"[^\r\n]*`，保证评测脚本中的中文注释行被稳定忽略。

---

### 2.2 语法分析（yacc）
文件：`rmdb/src/parser/yacc.y`

核心改造：
1. `SELECT` 子句结构扩展为：
   `SELECT selector FROM tableList optWhereClause optGroupByClause optHavingClause opt_order_clause`
2. `selector` 从“列列表”升级为“表达式列表”，并支持 `expr AS alias`。
3. `expr` 增加聚合表达式：
   - `SUM(col)` / `COUNT(col)` / `AVG(col)` / `MIN(col)` / `MAX(col)`
   - `COUNT(*)`
4. `condition` 从 `col op expr` 升级为 `expr op expr`（用于 HAVING 聚合表达式比较）。
5. `HAVING` 从单条件扩展为布尔组合：
   - `havingOrClause -> havingAndClause | havingOrClause OR havingAndClause`
   - `havingAndClause -> condition | havingAndClause AND condition`
6. 空产生式类型对齐：`optWhereClause/optGroupByClause` 返回空 vector，避免 `nullptr` 类型错误。

---

### 2.3 AST 与语义值（parser/ast）
文件：`rmdb/src/parser/ast.h`

新增与调整：
1. 新增 `AggType`、`AggExpr` 表示聚合函数。
2. 新增 `AliasExpr` 表示 `expr AS alias`。
3. `BinaryExpr::lhs` 从 `Col` 升级为 `Expr`。
4. `SelectStmt` 扩展：
   - `select_exprs`
   - `group_bys`
   - `having`（OR-of-AND 条件组）
5. 为兼容旧链路保留 `SelectStmt::cols`（由 `select_exprs` 中普通列抽取）。
6. `SemValue` 扩展：
   - `sv_exprs`
   - `sv_groupby`
   - `sv_having_and`
   - `sv_having_or`

---

### 2.4 语义分析（analyze）
文件：
1. `rmdb/src/analyze/analyze.h`
2. `rmdb/src/analyze/analyze.cpp`

新增中间语义结构：
1. `SelectItem`（是否聚合、聚合类型、列信息、输出名）
2. `HavingCond`（HAVING 条件原子）
3. `Query` 扩展：
   - `select_exprs`
   - `group_by_cols`
   - `has_having`
   - `having_conds`（二维结构，OR-of-AND）

语义处理能力：
1. 提取并消歧 `select_exprs/group_by/having`。
2. 聚合结果默认输出名生成与重名去重。
3. `AliasExpr` 别名覆盖输出列名。
4. HAVING 条件展开为二维条件组，供执行层直接判定。

健壮性检测（关键）：
1. `WHERE` 禁止聚合函数（任一条件命中即报错）。
2. `GROUP BY` 约束：
   - `SELECT` 中非聚合列必须在 `GROUP BY` 中。
   - `SELECT *` + `GROUP BY` 判非法。
   - 无 `GROUP BY` 且存在聚合时，不允许混入非聚合列。
3. `HAVING` 中非聚合列必须满足分组约束。
4. 聚合函数类型约束：
   - `COUNT(col)` 支持 `int/float/char`
   - `MAX/MIN/SUM/AVG(col)` 仅支持 `int/float`

---

### 2.5 计划制定（planner）
文件：
1. `rmdb/src/optimizer/plan.h`
2. `rmdb/src/optimizer/planner.cpp`

新增计划节点：
1. `PlanTag::T_Agg`
2. `AggPlan`（承载 `select_exprs/group_by_cols/having_conds`）

计划组装策略：
1. `SELECT` 仍先走原扫描/连接构建。
2. 若存在聚合/分组/HAVING，插入 `AggPlan`。
3. 外层保留 `ProjectionPlan`（兼容现有 portal 流程）。

---

### 2.6 最小可执行修改（execution）
文件：
1. `rmdb/src/execution/executor_agg.h`（新增）
2. `rmdb/src/portal.h`（`AggPlan -> AggExecutor` 分支）

`AggExecutor` 最小实现：
1. 内存物化后分组聚合。
2. 支持 `COUNT(*)/COUNT(col)/MAX/MIN/SUM/AVG`。
3. 支持 `GROUP BY`。
4. 支持 `HAVING`（OR-of-AND 判定）。
5. 结果列名沿用 analyze 阶段输出名（含别名/去重）。

---

## 5. 当前最小实现仍不足之处

1. 性能层面
- `AggExecutor` 为全量物化聚合，数据量大时内存和延迟压力明显。

2. SQL 语义完整性
- 当前聚焦题目要求，标准 SQL 的更多边界（特别是 NULL 语义）未完整覆盖。

3. 表达式能力
- 尚未支持更复杂的算术表达式、函数嵌套、HAVING 括号优先级控制等。

4. 调试/评测稳定性
- 云端评测与本地仍有微小格式差异风险，需要继续聚焦 `output.txt` 精确行为。

---

## 6. 后续修改建议（按优先级）

1. 强化评测一致性（最高优先）
- 对 `output.txt` 写入路径做统一封装，显式控制何时写结果、何时只写 `failure`。
- 增加“写入来源追踪开关”（仅本地调试），快速定位多写/漏写。

2. 完善健壮性规则回归集
- 固化非法用例矩阵：
  - WHERE 聚合（单条件/多条件）
  - SELECT 非分组列
  - HAVING 非分组非聚合列
  - 聚合类型非法（char 上的 MAX/MIN/SUM/AVG）

3. 提升执行性能
- 将 `AggExecutor` 从全量物化升级为哈希增量聚合或流式聚合。

4. 语义扩展
- 逐步支持更复杂表达式与 HAVING 括号优先级。
